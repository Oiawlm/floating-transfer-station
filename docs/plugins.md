# 插件作者指南

悬浮中转站的插件是**纯声明式**的：一个文件夹 + 一份 `plugin.json` 清单，不含任何可执行代码。本文是插件作者的能力参考：能力阶梯、两种插件类型的全字段说明、动作执行协议、资源预算、安装与排查。

> 边界原则：插件只通过宿主声明的贡献点扩展软件——文本整理（入库前自动应用）与卡片动作（用户主动触发）。插件**不能**改写应用的核心契约：内容持久化的原子性、置顶分区、批量顺序、拖放源数据、安全卸载边界等（见 [design-contracts.md](design-contracts.md)）。需要新贡献点时先在仓库开 Issue 讨论。

## 能力阶梯

| 层级 | 能力 | 状态 |
|---|---|---|
| L0 | `text-cleaner` 声明式文本整理：文字入库前自动应用正则规则 | ✅ 1.9.0 起 |
| L1 | `text-actions` 声明式卡片动作：右键菜单对选中文字卡应用规则，宿主统一提交 | ✅ 1.51.0 起 |
| L2 | 脚本插件（进程内脚本引擎，如 Jint） | 未立项，见下文准入条件 |
| L3 | 宿主 API 插件（完整 SDK、自有 UI 贡献点） | 远期 |

**L2（脚本插件）准入条件**：出现正则无法合理表达的真实插件需求时立项（例如需要字符码位运算、状态记忆或外部数据源）；进程内 Jint 为首选方案；「自动入库钩子」（插件在内容变动时自动执行）与权限门控需要单独授权，不随 L2 首版自动获得。

## 安装、启用与覆盖

- 把含 `plugin.json` 的插件文件夹放进**插件目录**（默认为数据目录的 `plugins/`，可在设置中更改），点击设置区的「重新扫描」或重启应用即可出现。
- 插件默认**全部禁用**；在设置中启用后立即生效并自动保存（状态文件为数据目录的 `plugins-state.json`，原子写入）。
- **同名覆盖**：用户目录中与内置插件同 id 的插件会覆盖内置版本；插件行会显示「内置 / 用户覆盖」徽章（悬停可见实际目录）。删除内置插件没有开关——移除用户目录中的同名插件文件夹并重新扫描即可恢复内置版本。
- 清单非法的插件仍显示在列表中（标红原因），但**不可启用**；修复 `plugin.json` 后点「重新扫描」。

## 类型一：`text-cleaner`（声明式文本整理）

启用后在文字**入库前**按插件列表序应用全部规则（自动采集与外部拖入共用同一管线）：

- 正则以 `CultureInvariant + Multiline` 编译：`^`/`$` 锚定每行；单条规则执行超时 100ms。
- **替换串是字面替换**：写什么替换成什么，`$1` 之类不会被解释（1.51.0 起严格执行——此前含 `$` 的替换串会被按 .NET 替换语义解释）。
- 任一规则超时或最终结果为空白 → **整体回退原文**（插件不得清空内容）。

```json
{
  "id": "whitespace-tidy",
  "name": "整理空白",
  "version": "1.0.0",
  "description": "统一换行、去行尾空白、压缩连续空行。",
  "kind": "text-cleaner",
  "textRules": [
    { "pattern": "\\r\\n|\\r|\\n", "replacement": "\r\n", "description": "统一换行为 CRLF" },
    { "pattern": "[ \\t]+(?=\\r?\\n|$)", "replacement": "", "description": "去行尾空白" },
    { "pattern": "(?:\\r\\n){4,}", "replacement": "\r\n\r\n\r\n", "description": "压缩 3 行以上连续空行" }
  ]
}
```

### 字段参考（text-cleaner）

| 字段 | 必填 | 约束 |
|---|---|---|
| `id` | ✅ | 3–64 位小写字母/数字/连字符，字母数字开头结尾，全局唯一 |
| `name` | ✅ | ≤40 字符 |
| `version` | ✅ | 语义版本号（如 `1.0.0`） |
| `description` | — | ≤200 字符 |
| `kind` | ✅ | `"text-cleaner"` |
| `textRules` | — | ≤32 条；每条 `pattern`（1–512 字符、可编译正则）＋`replacement`（≤512 字符）＋可选 `description`（≤120） |

## 类型二：`text-actions`（声明式卡片动作，L1）

动作插件不出现在自动管线里；用户在**文字卡上右键 →「插件动作」**主动触发：

- **入口可见性**：`selection: "single"` 的动作要求选集**恰为一张文字卡**（含图片卡的选集不满足）；`selection: "multi"` 的动作要求选集中**文字卡 ≥2**（图片卡忽略；纯图片选集无动作可用）。无可执行动作时不显示菜单分组。
- **输入**：板序选中的文字卡快照（稳定 id + 全文）。
- **输出**：v1 只支持 `output: "replace"`——逐卡新文本经宿主批量替换管线写回原卡（Ctrl+Z 可恢复）。

### 动作执行协议（宿主统一提交，插件只提议）

- **全有或全无**：管线对整批选集执行，任何一张卡失败（规则超时、预算超限、输出超限）→ 整批放弃，给出一句可读原因，**不发生任何修改、不静默截断**。
- **不得清空**：某卡整理结果 trim 后为空 → 该卡跳过、保留原文并计数（提交后在状态条注明），其余卡照常提交。
- **并发守卫**：执行期间用户手工编辑过的卡（正文与快照不符）→ 整批放弃并提示。
- **单飞**：动作执行中不允许再触发动作。
- **撤销**：成功提交是一批可撤销操作；Ctrl+Z 逐卡恢复原文（与 AI 整理同族语义）。

### 资源预算（超出即整批可读失败）

| 预算 | 值 |
|---|---|
| 整次调用总时长 | 2000 ms（叠加在单规则 100ms 之上） |
| 选集总输入字符 | 100,000 |
| 单卡输出字符 | 50,000 |
| 试运行输入字符 | 10,000 |

### 两种替换语义（重要）

| 插件类型 | 替换串语义 | 示例 |
|---|---|---|
| `text-cleaner` | **字面替换**：`$1` 就是文字 "$1" | `[ \t]+` → `$` 会把匹配替换成字符 `$` |
| `text-actions` | **.NET 替换语义**：`$1`/`${name}` 引用捕获组，`$$` 表示字面 `$` | `([A-Za-z])([\u4e00-\u9fff])` → `$1 $2` 在中英文间补空格 |

### 字段参考（text-actions）

在 text-cleaner 全部字段基础上，`kind` 为 `"text-actions"` 时必须声明 `actions`（1–16 个动作，字段见下）：

| 动作字段 | 必填 | 约束 |
|---|---|---|
| `id` | ✅ | 3–64 位小写字母/数字/连字符，**插件内唯一** |
| `title` | ✅ | ≤40 字符（右键菜单项文案） |
| `accept` | ✅ | v1 只支持 `"text"` |
| `selection` | ✅ | `"single"` 或 `"multi"`（见上文可见性） |
| `output` | ✅ | v1 只支持 `"replace"`；`"new-cards"` 是保留字，校验拒绝并提示 |
| `rules` | ✅ | 1–32 条，同 text-cleaner 规则机器，另支持 `when` |
| `settings` | — | 0–8 个声明式设置字段，见下 |

**规则字段 `when`**：引用本动作声明的 **bool** 设置 key；运行时该设置关闭则此规则不参与。全部规则被门控关闭的动作不出现在菜单中。

**设置字段（`settings[]`）**：在设置窗口插件行内展开渲染，值按插件 id 原子持久化到 `plugins-state.json`，改动即时生效（试运行与菜单执行都按最新值）：

| 字段 | 约束 |
|---|---|
| `key` | 3–32 位小写字母/数字/连字符，动作内唯一 |
| `label` | ≤40 字符（设置界面显示） |
| `type` | `bool`（默认 false）、`choice`（`options` 2–8 项、每项 ≤40 字符、`default` 必填且必须是 options 中一项）、`text`（默认空、≤200 字符） |
| `default` | 与 `type` 吻合（bool 用 `true`/`false`，choice/text 用字符串） |

> v1 语义消费点：`bool` 设置经规则的 `when` 影响执行；`choice`/`text` 的声明、持久化与 UI 编辑已就绪，语义消费点为 L2 预留。

### 完整示例（内置插件 `typography-tidy`）

```json
{
  "id": "typography-tidy",
  "name": "中文排版整理",
  "version": "1.0.0",
  "description": "中英文之间加空格、压缩连续空格，并可选把紧跟中文的半角标点转为全角。",
  "kind": "text-actions",
  "actions": [
    {
      "id": "tidy-card",
      "title": "整理这张卡片",
      "accept": "text",
      "selection": "single",
      "output": "replace",
      "settings": [
        { "key": "punct-to-fullwidth", "label": "半角标点转全角（仅限紧跟中文时）", "type": "bool", "default": false }
      ],
      "rules": [
        { "pattern": "([A-Za-z0-9])([\\u4e00-\\u9fff])", "replacement": "$1 $2", "description": "中英文间补空格" },
        { "pattern": " {2,}", "replacement": " ", "description": "压缩连续空格" },
        { "pattern": ",(?=[\\u4e00-\\u9fff])", "replacement": "，", "when": "punct-to-fullwidth" }
      ]
    }
  ]
}
```

## 试运行与调试

- 设置 → 数据与维护 → 插件：动作插件的每个动作提供「试运行…」——输入 1–10000 字符、运行、查看输出/总耗时/规则命中计数。试运行**按当前设置现建管线**（复用正式加载器口径），只读演练、不改卡片。
- 校验错误带定位：动作索引/id、规则序号、设置 key 都会出现在错误文案里（清单非法时显示在插件行）。
- 启停、设置修改即时生效，无需重启；增删插件文件夹后点「重新扫描」。

## 兼容与失败排查

| 现象 | 原因与处理 |
|---|---|
| 插件没出现在列表 | 目录里缺 `plugin.json`，或 JSON 语法错误（插件行会显示「无法加载」与原因） |
| 插件可见但开关置灰 | 清单校验失败——按插件行的红色原因修复后「重新扫描」 |
| 右键菜单没有「插件动作」 | 插件未启用；或选集组成不满足任何动作的 `selection`；或该动作全部规则被 `when` 关闭 |
| 动作提示「选中的卡片内容已变化」 | 执行前卡片被手工编辑——重试即可 |
| 动作提示超时/超预算 | 规则过重（灾难性回溯）或选集过大——精简 pattern、缩小选集 |
| 升级后行为变化 | 1.51.0 起 `text-cleaner` 替换串严格执行字面替换（此前 `$` 序列会被解释）；如依赖旧行为请把 `$` 写成 `$$` |
