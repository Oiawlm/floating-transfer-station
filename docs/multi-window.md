# 多窗口并行开发协议

多个窗口（会话）在同一仓库并行开发时的工作区隔离、冲突面申报与串行集成编排。原则承接[贡献指南](../CONTRIBUTING.md)「并行开发与分支纪律」（版本是发行属性，不是分支属性）与[发布指南](releasing.md)「发行列车」（一列串行、四道防线）；工作区隔离默认由独立 clone 调整为 worktree 兄弟目录，其余纪律不变；本文不重复其内容，只补齐并行执行期的角色分工与协调介质。追踪 Issue：#99。

协议零工具：协调介质是自包含执行提示词与 git 原生命令，不引入脚本、锁文件或编排工具——工作区分区把并发冲突压缩到共享轨道文件的最小面，剩余冲突按轨道约定处理，无需文件锁。

## 三角色职责

| 角色 | 活动目录 | 可写范围 | 产出 |
|---|---|---|---|
| 规划窗口 | 主检出（只读） | 仅落盘 gitignored 交接目录的执行提示词（不建分支、不碰受跟踪文件） | 自包含执行提示词：唯一分支名 `<类型>/<slug>`、预期触碰文件清单、可核对验收清单 |
| 执行窗口 | 自建 worktree | 仅本 worktree | 分支创建即推送、每提交必推、PR 跟绿质量门；无集成窗口时收尾自办合并与列车 |
| 集成窗口 | 主检出（唯一写者） | 主检出受跟踪内容（经逐 PR 合并与发行列车操作） | 串行合并、一列发行列车、GitHub Release、装机、归位、本地文档回写 |

规划窗口的执行提示词按维护者交接惯例落盘为 `<日期>-<slug>-execution-prompt.md`（gitignored 本地交接目录，不入库），这是规划窗口唯一的写动作，不触碰任何受跟踪文件；文件本身即协调介质：新窗口以提示词全文为首条消息启动，脱离规划会话仍可独立执行到验收。

## worktree 规范

- 隔离单元是 **git worktree 兄弟目录**：`../悬浮中转站-worktrees/<slug>/`（与仓库检出同级）。**禁止**放在仓库内 `.worktrees/`——`git clean -fdx` 会连带清空，且干扰工具扫描。独立完整 clone 留给需要完全隔离 refs/config/stash 的环境；任何情况**不得共享同一 checkout**。
- 创建模板（slug 换成实际，创建即推送）：

  ```bash
  git fetch origin
  git ls-remote --heads origin <类型>/<slug>   # 必须为空；非空=撞名，报告用户或规划窗口裁决、不自行改名
  git worktree add "../悬浮中转站-worktrees/<slug>" -b <类型>/<slug> origin/main
  git -C "../悬浮中转站-worktrees/<slug>" push -u origin <类型>/<slug>
  ```

- **gitignored 本地指令文档不随 worktree 复制**：创建后手动拷入 `AGENTS.md`、`PROJECT_GUIDE.md` 等本地指令文件与本地交接目录（不拷则规则链断裂）；用后清理：`git worktree remove <路径> && git worktree prune`。
- 主检出保持 on main，受跟踪内容由集成窗口独占写入；仅有的例外是两个不入库动作：规划窗口把执行提示词落盘 gitignored 本地交接目录、收尾执行窗口的本地文档回写。worktree 内每文件单一写者。

## 错峰与并发

三角色按窗口开工时自声明，错峰合法：N 个规划 + M 个执行 + 1 个集成可任意交叠。硬约束只有三条：

- 一个执行窗口同一时刻只占一个分支、一个 worktree；
- 主检出受跟踪内容同一时刻只有一个写者（集成窗口）；gitignored 本地文档的写入各自作用于不同文件（提示词按 `<日期>-<slug>` 唯一命名、回写只在归位时发生一次），无需互斥；
- 发行列车同一时刻全局只跑一列（`release/vX.Y.Z` 分支名即锁保证，见[发布指南](releasing.md)）。

## 冲突面申报与轨道约定

- **冲突面申报**：每份执行提示词必须申报「预期触碰文件」清单，集成窗口据此预判冲突、按依赖/优先级排序合并；规划窗口派发时也可按冲突面预分区，把不相交的文件集分给并行窗口；执行中确需触碰清单外文件时，先在 PR 描述补充申报再继续。
- **轨道文件冲突约定**（同步合并与列车重放通用，详见[贡献指南](../CONTRIBUTING.md)「并行开发与分支纪律」）：
  - `CHANGELOG.md`「未发布」区冲突 = **保留双方条目**（两类改动都该被发行列车消费）；
  - `version.txt` 与 README「下载」段冲突 = 流程违规信号（功能分支本不该改这两个文件），以远端 main 为准重放；
  - 设计契约编号撞车（[设计契约清单](design-contracts.md)）= 后同步者（同步 main 时点较后者）让位重编号，并同步全部引用；

## 串行集成与批量发行

1. 逐 PR 串行合并（顺序按依赖/优先级）：每支先把最新 `origin/main` 同步进分支（`git fetch origin && git merge origin/main`），按上述轨道约定解冲突 → 推送 → 等质量门「格式、测试与构建」绿 → 合并 PR。
2. **掉队分支**：质量门持续红或冲突不可解的分支移出本批、不阻塞列车；分支与 PR 保留（工作已推送不丢），由集成窗口顺延下一批承接处理。
3. 全部合并后走**一列**发行列车：按[发布指南](releasing.md)全流程——`release/vX.Y.Z` 短分支、四道防线、`build-release.ps1 -ForRelease`、用合并后 main 的 CI `release-candidate` 产物发 Release（分支上产物仅作门禁证据）。
4. 装机全局串行：版本核对目标版本**大于**本机已装为硬门，优雅关闭运行实例 → 静默原地更新 → 重启并验证版本与自启。
5. **本地文档回写与归位**：先把 worktree 内修改过的本地指令文档写回主检出（回写前重读主区版本，发现并行改动先比对合并；批量模式由集成窗口执行，流式模式由收尾执行窗口执行），再切 main、`pull --ff-only`、删本地与远端功能分支、`git worktree remove`、`git fetch --prune --tags`。
6. 流式模式（兼容单窗口现状）：单个执行窗口自办 PR + 列车 + 装机；同一时刻全局仍只能有一列列车——`release/vX.Y.Z` 分支名即锁在推送时生效，被拒者按[发布指南](releasing.md)重放顺延。

## 提示词模板三则

占位符 `<类型>`、`<slug>`、`<路径>`、`<日期>` 按实际替换；模板与具体任务解耦。

### 规划窗自检清单

```text
□ 总目标一句话可核对，分项产出可验收（Done when 口径）。
□ 已给唯一分支名 <类型>/<slug>（不带版本号），并提示开工时先核对远端不撞名。
□ 已列预期触碰文件清单（冲突面），与验收范围对应。
□ 冷启动阅读清单按优先级排列，并标注禁读范围防上下文膨胀。
□ 已锁定决策逐条列出并标注「不得改」；边界、红线与等待上限单独成节。
□ 提示词自包含：脱离本会话后，新窗口可独立执行到验收。
```

### 执行窗 GOAL 骨架

```text
读取 <路径> 全文作为你的执行提示词并严格按其落地：
以该文件验收清单为唯一完成口径，逐条以命令输出与文件实据判定；本目标仅此一项，做到即停。
（提示词须自包含：背景与冷启动阅读序、锁定决策、Phase 任务、铁律、验收清单。）
```

### 集成窗骨架

```text
读取 <路径> 全文作为你的执行提示词并严格按其落地：
1. 逐 PR 串行合并：同步 origin/main → 质量门绿 → 合并；掉队分支移出本批不阻塞。
2. 合并完后走一列发行列车：release/vX.Y.Z → 构建入口 -ForRelease →
   用合并后 main 的 release-candidate 产物发 Release。
3. 装机（版本核对硬门，全局串行）→ 归位 + 本地文档回写 → 执行报告落交接目录。
```
