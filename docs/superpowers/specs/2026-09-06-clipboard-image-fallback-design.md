# 剪贴板损坏图片表示回退

## 结果与范围

同次复制通常提供多个图片表示。保留现有“像素面积优先、面积相同优先 WPF 位图”的选择顺序；较优编码表示只有头信息可读、完整解码失败时，继续尝试这次读取已冻结的其他表示。至少一个可用表示应保存一张 PNG；全部不可用才报告失败。

用户已授权直接推进下一项可独立验证的改进。本次不改变剪贴板读取事务、默认接收分类、队列顺序、存储格式、外部拖入静态图片约束或 UI 操作入口。

## 当前证据与候选判断

`ImageNormalizer.NormalizeClipboardCore` 使用 `Image.Identify` 计算大小，排序后只取一个候选。`Identify` 能读取头信息并不保证 `Image.Load` 能解码像素；当前首个候选解码失败会直接结束整次导入。

曾先检查待更新的 ImageSharp PR #5：旧 CI 因测试依赖 Color 隐式像素转换而编译失败。当前 3.x 最新仍为 3.1.12；4.x 直接引用要求构建许可证，不能在本次无需用户身份/密钥的范围内完成。保留该 PR，不申请或绕过许可。[Six Labors 官方说明](https://sixlabors.com/posts/licence-enforcement-changes/)

## 方案

采用按现有优先级逐个完整解码，在首个成功解码的表示上执行原 PNG 保存流程。预先解码所有表示会增加不必要的图片内存；重新读取系统剪贴板会改变冻结内容与通知时序，因此不采用。

只将 `Image.Load` 抛出的 `UnknownImageFormatException`、`InvalidImageContentException` 视为该表示不可用。文件写入、PNG 编码、移动及取消处于回退捕获范围之外，必须直接传播。每次尝试前检查取消；成功加载的图片由调用方及时 Dispose。

耗尽候选时使用现有“Clipboard does not contain a usable image representation.”的 `InvalidDataException`，统一无可用表示的失败。上层仍报告原有“本次图片未保存，请重新复制。”，不改变内容保存事务。

## 完成证据

- 合成截断 PNG 的 Identify 成功而 Load 失败，证明失败发生在解码阶段。
- 改前包含损坏大图和有效小图的公共 API 测试失败；改后有效编码图或 WPF 位图被保存，像素、尺寸、指定 ID 和 PNG 输出正确。
- 较大有效候选仍优先，同面积仍优先 WPF 位图；全部损坏、取消、已有目标和写入失败不遗留临时文件或覆盖目标。
- 图片归一化与剪贴板捕获相关回归通过，完整格式/Release 测试/严格构建、打包及 CI 安装态检查通过。
- 使用合成内容提供真实 WPF 显示证据，产物只保存于忽略目录。B-005/B-006 未稳定复现，不将本次修复归因于这两项观察。
