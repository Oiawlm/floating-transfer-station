# 撤销与回收站(设计草案)

> 状态:切片 1(面板聚焦 `Ctrl+Z` 会话级撤销)已随 1.11.0 落地;回收站等后续切片未实施。
> 2026-09-25 夜间循环,wbx cn lane 起草、主代理评审修订。决策框架见 [持续改进循环](../../improvement-loop.md);本文不构成发布承诺。

## 用户结果

误删不再造成数据丢失:删除后可按 `Ctrl+Z` 立即恢复最近一次删除(含批量),也可稍后从回收站找回;回收站超容量后自动清理最旧条目。

## 撤销语义

- 覆盖范围:仅删除(单选/多选/清空),不含移动、置顶、改名。清空是否并入撤销栈为 UNKNOWN,取决于其是否复用批量删除路径。
- 栈深:建议最近 20 次,超限丢最旧(具体值待定)。
- 与批量删除:一次批量删除为一个撤销单元,恢复时按源显示顺序原样重建,保持置顶区/普通区归属。
- **作用域(评审修订)**:`Ctrl+Z` 必须是**面板持有键盘焦点时**的快捷键,**绝不能注册为全局热键**——全局注册会抢占所有应用的撤销键。不与 1.10.0 的全局快捷键基建混用。
- 不可撤销项:保存失败已回滚的操作本身无需撤销;已被回收站容量策略清除的条目不可撤销。

## 回收站语义

- 入口:悬浮面板底部按钮 + 设置窗口区块(是否需快捷键为 UNKNOWN)。
- 容量与保留:建议条目数 + 图片总字节双上限,超限按删除时间先进先出清理。持久化与否:倾向写入 Data 目录以便重启找回,磁盘成本 UNKNOWN;切片 1 可先做会话级。
- 恢复位置:回到原分类,置顶/顺序按删除时快照还原。原分类结构已变化时的落点为 UNKNOWN(建议按时间戳插入普通区)。
- 图片实体:删除条目时文件保留在 `images/`,仅在回收站清理/清空时删除;恢复时文件仍在;需引用计数避免误删仍被引用的文件。
- 与「清空」按钮:清空应等于「批量移入回收站」而非直接销毁,并保留可恢复提示;回收站内清空才是不可逆销毁并触发图片文件清理。

## 技术挂点

- 删除收敛到统一入口(移入回收站 → 持久化),撤销/恢复/清理为独立路径。
- 不得触碰保存失败回滚与原子性:回收站写入同样原子写,失败时维持对象/状态/顺序/选择/滚动恢复语义。
- 图片清理时机从「删除条目」迁移到「回收站清理」,顺序与原子写一致。

## 分期建议

- 切片 1(一晚 M):面板聚焦时 `Ctrl+Z` 撤销最近一次删除,会话内小栈,不删图片文件,无回收站 UI。
- 切片 2:持久化回收站 + 容量策略 + 批量恢复。
- 切片 3:清空按钮接入、图片清理时机迁移、设置项。

## 风险清单

1. 图片引用计数错误致文件误删,恢复后图片失效。
2. 恢复时原分类或置顶归属已变化,快照与现状不一致。
3. 容量策略清理过快,用户来不及恢复。
4. 持久化回收站增大磁盘占用,需与「卸载只删登记 Data 目录」边界保持一致。
