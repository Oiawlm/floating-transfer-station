# Esc 取消选择快捷键设计

## 用户结果

用户在当前展开分类中完成多选或 `Ctrl + A` 全选后，可以按 `Esc` 一次取消全部卡片选择。取消后批量置顶按钮和已选数量徽标随选择状态一并收起，不写入任何内容或设置。

## 方案选择

采用 `MainWindow` 已有的 `PreviewKeyDown` 入口处理 `Esc`。这是窗口现有 `Backspace` 删除快捷键所在的边界，能够直接访问真实的 `BoardList` 选择状态，并复用 `SelectionChanged` 对批量操作界面的更新。

没有采用新的 `RoutedUICommand`，因为 WPF 没有与“清除列表选择”语义匹配的标准应用命令，自定义命令只会为一个局部动作增加命令绑定。也没有采用 `Ctrl + Shift + A`，因为 `Esc` 更符合“取消当前操作”的预期，而且不会与分类名称编辑框的文字选择命令冲突。

## 行为边界

- 仅当窗口未进入关闭流程、当前面板已展开、键盘焦点不在 `TextBoxBase` 中且至少有一张卡片被选中时，`Esc` 才取消当前列表的全部选择并把按键标记为已处理。
- 分类名称编辑框拥有焦点时，窗口不处理 `Esc`，继续由编辑器现有逻辑取消本次改名。
- 面板已收起时不清除隐藏选择，保持现有“收起不丢选择”的契约。
- 没有选择时不吞掉 `Esc`，也不触发保存。
- 单卡或批量置顶正在慢速保存时，较晚发生的 `Esc` 取消意图优先；保存完成不得恢复操作开始时的旧选择。
- 不改变卡片内容、顺序、置顶分区、拖放载荷、持久化格式或卸载范围。

## 数据流与失败处理

快捷键递增窗口内的选择取消版本，再调用 `BoardList.UnselectAll()`。现有 `SelectionChanged` 事件更新已选数量、删除按钮说明和批量置顶按钮。单卡与批量置顶在开始时捕获该版本，异步保存完成后仅在版本未变化时恢复为排序而暂时丢失的选择；滚动恢复不受影响。快捷键自身没有磁盘保存或需要回滚的失败路径。

## 验证

真实 STA WPF 交互测试覆盖：展开态清除选择且不保存、分类名称编辑器真实路由取消改名并保留卡片选择、折叠态保留隐藏选择、空选择与关闭态不吞键，以及单卡/批量置顶慢保存完成后不复活旧选择。生命周期测试锁定 README 和更新记录中的公开说明。最终运行相关测试、格式验证、Release 全量测试、严格 Release 构建和 `git diff --check`，并生成未提交的真实界面前后状态截图。
