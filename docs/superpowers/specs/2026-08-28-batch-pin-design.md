# 批量置顶与批量取消置顶设计

## 目标

让用户在当前分类中选中多张卡片后，通过一次明确操作统一改变所选卡片的置顶状态，同时保持单卡图钉、置顶分区、批内顺序、选择状态、滚动位置和原子保存语义。

## 已选方案

在顶部操作区增加独立的批量图钉按钮。按钮仅在至少选中一项时显示并可操作：

- 所选卡片中只要存在未置顶项，按钮语义为“置顶已选 N 项”，点击后把全部所选卡片置顶。
- 所选卡片全部已经置顶时，按钮语义为“取消置顶已选 N 项”，点击后把全部所选卡片取消置顶。
- 卡片自身的图钉继续只作用于被点击的单张卡片，不因该卡片是否位于选择集合中而改变语义。

按钮复用现有标题栏操作按钮样式和图钉图形，并通过工具提示及自动化名称暴露当前操作。选择计数仍由删除按钮上的角标展示，避免在狭窄标题栏重复占位。

## 备选方案与取舍

1. 让卡片图钉在多选时自动作用于整批。入口更省空间，但同一控件的作用域会随选择状态暗中变化，容易误操作，因此不采用。
2. 同时显示“批量置顶”和“批量取消置顶”两个按钮。语义最直白，但标题栏空间有限，而且任一时刻通常只需要一种主操作，因此不采用。
3. 在顶部增加一个状态自适应按钮。作用域明确、占用最小，并能保留单卡操作契约，因此采用。

## 数据流与原子性

选择变化时，窗口根据当前选择集合计算目标状态并刷新按钮的可见性、工具提示和自动化名称。点击按钮时按当前分类中的显示顺序捕获所选 ID、分类与滚动偏移，然后调用已有 `BoardMutationService.SetPinnedAsync`：

1. `BoardService.SetPinnedMany` 统一改变状态，并把所选项作为一个保持源顺序的批次移动到目标分区顶部。
2. `BoardMutationService` 只保存一次快照。
3. 保存成功后恢复原选择集合和显式滚动偏移。
4. 保存失败时由现有撤销对象恢复对象、状态和精确顺序，再恢复选择与滚动偏移，并显示现有错误消息。

该功能不改变 `board.json`、图片目录、拖放格式、跨分类移动规则或卸载边界。

## 并发与边界

- 点击时重新读取选择，空选择直接返回，避免异步布局变化产生无目标操作。
- 批量操作继续经过共享的 `BoardOperationGate`，与删除、移动、剪贴板写入串行化。
- 保存进行期间，选择角标和删除作用域保持当前状态；完成后仍恢复最初选择。
- 混合选择统一转为置顶；只有全置顶选择才执行取消置顶。这保证按钮每次点击都有确定结果，不会反转每项而产生新的混合状态。
- 用户切换分类时现有逻辑清空选择，批量按钮随之隐藏。

## 验证

自动测试覆盖：

- 空选择隐藏批量按钮；混合或全未置顶选择显示“置顶”，全置顶选择显示“取消置顶”。
- 混合选择一次置顶并保持批内源顺序、未选项状态、选择集合和滚动位置。
- 全置顶选择一次取消置顶并保持批内源顺序。
- 慢保存期间选择计数和批量删除作用域不退化。
- 保存失败时恢复状态、精确顺序、选择集合、滚动位置和错误提示。
- 单卡图钉仍只切换被点击项。
