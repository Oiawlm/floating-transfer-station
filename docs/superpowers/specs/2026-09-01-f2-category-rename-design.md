# F2 分类改名设计

## 用户结果

Windows 用户可以在面板展开时按标准 `F2` 键改名当前分类，不必精确双击窄分类标签。双击改名继续保留，两种入口进入同一个编辑器并保持相同的全选、中文输入法、提交、取消和保存失败恢复行为。

## 方案选择

采用窗口级 `PreviewKeyDown` 入口，并把双击和 `F2` 收敛到同一个开始改名辅助方法。辅助方法只负责让目标分类进入编辑态，并在现有分类标签中找到对应编辑器后异步聚焦、全选；名称限制、IME 组合、持久化和失败回滚仍由现有路径负责。

没有新增 `RoutedUICommand`：`F2` 只有当前窗口一个消费者，命令绑定仍需相同的焦点与面板状态守卫，不能减少代码或风险。也没有新增可见按钮：已有双击入口和新增快捷键已经覆盖鼠标与键盘，额外控件会挤占狭窄标签轨并扩大 UI 验收范围。

## 行为边界

- 仅在窗口未进入关闭流程、面板已展开、当前活动分类存在、没有分类正在改名、键盘焦点不在 `TextBoxBase` 中且没有 Ctrl、Shift、Alt 或 Windows 修饰键时处理 `F2`。
- 快捷键只改名当前展开分类，不切换默认接收分类，也不改变卡片选择。
- 成功进入编辑态后吞掉 `F2`，聚焦当前分类名称编辑器并全选现有名称，便于直接输入替换。
- 面板折叠、窗口关闭或分类名称编辑器已经激活时不处理 `F2`；文本框保留自己的键盘行为和当前草稿。
- 双击分类标签继续改名该标签，并通过同一个辅助方法获得与 `F2` 一致的聚焦和全选行为。
- 不改变分类数量、内容模型、持久化格式、默认接收分类、置顶分区、批量顺序、拖放载荷或卸载范围。

## 数据流与失败处理

窗口收到 `F2` 后先完成关闭、焦点、展开状态、活动分类和编辑态守卫，再解析活动分类对应的现有标签。只有标签可用并成功进入编辑态时才标记事件已处理。后续 `Enter`、`Esc`、失焦提交、名称长度限制、IME 组合处理以及 `SaveCategoryNameAsync` 的串行保存和失败恢复保持不变，因此快捷键不会引入第二套状态或持久化路径。

## 验证

真实 STA WPF 交互测试锁定：展开态 `F2` 只编辑活动分类、编辑器获得焦点且全选、卡片选择和默认分类不变、未发生保存；折叠态、关闭态和已有文本编辑焦点不处理。双击现有回归继续证明旧入口可用，并新增共享入口断言防止两条路径漂移。生命周期测试锁定 README、CHANGELOG 与 ROADMAP 的公开说明。

最终运行相关测试、格式验证、Release 全量测试、严格 Release 构建和 `git diff --check`；通过真实 WPF 窗口截图确认按下 `F2` 后当前分类名称处于可见编辑和全选状态。验证产物只写入被忽略的 `artifacts/`。
