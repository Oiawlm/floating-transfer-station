# Ctrl+A 全选当前分类设计

## 用户结果

当悬浮中转站展开且焦点不在文本编辑器中时，按 `Ctrl+A` 会选中当前分类中的全部卡片。用户随后可以直接使用现有的批量置顶、批量移动或批量删除能力，不必逐项勾选。

分类名称编辑框仍保留 Windows/WPF 的原生 `Ctrl+A` 语义，只全选编辑框文字，不扩大卡片选择。空分类执行该命令时不产生状态变化。

## 方案比较

1. **复用 `ApplicationCommands.SelectAll`（采用）**：在主窗口增加路由命令绑定，让 WPF 从当前焦点开始解析命令。`TextBox` 的内置命令处理优先，窗口只处理未被文本编辑器消费的全选命令。这与平台习惯一致，且无需手工解析键盘修饰键。
2. **在 `PreviewKeyDown` 中判断 `Ctrl+A`**：实现短，但依赖 `Keyboard.Modifiers` 全局状态，自动化测试和输入法/焦点边界更脆弱，还需要显式绕开文本编辑器。
3. **新增自定义 `RoutedUICommand`**：可完全控制命令，但重复了 WPF 已有的 Select All 语义，并可能与文本编辑器的同一手势竞争。

## 交互与数据流

主窗口为 `ApplicationCommands.SelectAll` 注册 `CanExecute` 与 `Executed`。当窗口未关闭、面板已展开、当前分类非空且命令没有被文本编辑器先处理时，命令可执行；执行端调用 `BoardList.SelectAll()`。

既有 `BoardList_SelectionChanged` 继续负责同步选择数量徽标、删除范围和批量置顶按钮。命令不调用 `BoardService`、`BoardMutationService` 或 `IBoardStore`，因此不会保存、重排、置顶、移动或删除内容。

## 边界与失败处理

- 当前分类为空时命令不可执行。
- 面板收起时命令不可执行，并保留收起前已有的选择，不会选中隐藏卡片。
- 窗口关闭流程已经开始时命令不可执行。
- 分类名称编辑框拥有焦点时，WPF 原生文本全选生效，卡片选择集合不变。
- 命令只作用于 `BoardList.ItemsSource` 所代表的当前分类，不跨分类选择。
- 现有分类切换清空选择、自动收起保留选择、批量顺序、拖放源数据和持久化原子性语义保持不变。
- 该操作没有 I/O，因此不存在部分保存或回滚路径。

## 验证

先新增真实 STA WPF 交互测试，证明当前窗口没有可执行的全选命令；实现后验证命令手势为 `Ctrl+A`、当前分类全部卡片被选择、数量徽标和批量入口同步、存储写入次数仍为零。另一个测试让分类名称编辑器获得焦点，验证 `ApplicationCommands.SelectAll` 只选择文字且不扩大卡片选择。三个负向测试分别锁定当前分类为空、面板收起和真实关闭流程中的不可执行语义，其中收起测试还验证既有选择保持不变。
