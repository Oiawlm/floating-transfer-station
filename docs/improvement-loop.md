# 持续改进循环

这份文档定义"悬浮中转站"的夜间自动改进循环：谁提方向、怎么选方向、怎么落地、哪些既有设计绝对不能被新功能改回去。自动任务与人工会话都按本文执行；与 `AGENTS.md`、`PROJECT_GUIDE.md` 冲突时以后者为准。

## 第一性原理：三类算力各司其职

| 算力 | 特点 | 分配的工作 |
|---|---|---|
| wbx 双 lane（WorkBuddy · DeepSeek V4.1 Flash，国际版免费 + 国内版近免费） | 无工具、纯文本进出、单轮完成、近零成本 | 发散：提案、评审给定材料、批量文本 |
| GLM 5.3 / 5.3 Flash（主代理） | 有工具链、能写代码、能联网 | 收敛决策、调研、实现、测试、发布 |
| 夜间窗口（23:15 起） | 5.3 Flash 几乎不限量 | 自动任务排在这个时段 |

外部 worker 的提案是**原材料**，不是决定。所有采纳都要经主代理按决策框架校验；worker 结论中涉及时效的事实必须由主代理核实。

## 每晚流程（23:15 自动触发）

1. **读状态**：`AGENTS.md`、本文、`ROADMAP.md`、`CHANGELOG.md` 未发布区、`git log -5`、当前候选池。
2. **备料**：写一份 ≤2000 字的提案材料（软件现状、已冻结边界、已在候选池的方向清单、近期新增弱点）。候选池里已有的方向要列出，避免重复提案。
3. **发散**：`wbx doctor` 通过后，fanout 双 lane（`as: ai` 与 `as: cn`）各提 5 个方向，合计 10 个。doctor 失败或连续 ≥2 个任务失败时，本轮提案由主代理自己生成 10 个并在日志中如实记录降级原因。
4. **收敛**：合并 10 个提案与候选池，按决策框架选出**当晚可完成的最小垂直切片**。两个 lane 高度重合的方向视为强共识信号，优先。
5. **实现**：新分支 `feature/loop-<日期>-<slug>`；遵守全部冻结清单；Core 改动保持跨平台（Mac 端当前暂停开发：不改 Mac UI，但不得破坏 Mac 编译与测试）；补自动回归；UI 变化产出真实截图。
6. **验证与交付**：质量门四连（见 `PROJECT_GUIDE.md`）→ `CHANGELOG.md` 未发布区 → 提升 `version.txt` → 提交、推送、PR、等 CI `quality` 汇总绿 → 合并 main → 按 `docs/releasing.md` 统一发行（Windows 与 Apple Silicon 同一 Release）→ 优雅关闭本机运行实例、静默原地更新、重启并验证版本与自启。
7. **沉淀**：当晚提案、决策与结果追加到 `docs/research/loop-<YYYY-MM>.md`；未采纳但可留的提案并入候选池；提交文档。

失败规则：质量门不过就修复；03:30 仍不过则停在分支、记录原因、**不发版**。任何步骤失败都如实记录，不虚报、不降低门槛凑发布。

## 决策框架

对每个候选按四维打分（1–5）：

- **用户感知**：普通用户每天能感到的变化吗？
- **成本**：当晚能否以最小垂直切片完成（S ≤ 半晚，M ≤ 一晚，L 需拆分）？
- **风险**：触碰冻结清单或持久化语义的减分；纯增量加分。
- **共识**：双 lane 是否同时提出；是否在候选池里被反复触发。

得分相同取用户感知更高者。`L` 级方向先产出设计文档进候选池，不当晚硬做。

## 设计冻结清单（新功能不得回退）

以下是已设计定型的行为，除非用户当次明确要求，任何改动不得改变它们；发现冲突时停下来问用户，不自行动刀：

1. 磁盘写入原子性；保存失败时对象、状态、顺序、选择与滚动位置恢复（`LocalStore`/`BoardMutationService`）。
2. 分类内始终先置顶区后普通区；批量操作保持源显示顺序；批量拖放保持源数据与选择作用域。
3. 卸载只删除应用登记并管理的 `Data` 目录，不扩大到用户选择的父目录。
4. 复盘标签不接收剪贴板或拖放内容；按天 Markdown、自动保存与外部变更合并语义不变。
5. 设置改动即时生效并自动原子保存；开机自启 Run 值只在用户显式切换时写入。
6. 贴边一侧窗口边缘与屏幕平齐；右缘裁切、展开/收起节奏与既有动效开关语义不变。
7. 编辑器（含分类改名）持有键盘焦点期间面板不自动收起。
8. 单实例锁；安装/数据目录只认安装器登记；`version.txt` 是唯一版本来源。
9. 插件系统边界（1.9.0 起）：声明式清单、默认全部禁用、插件不得把内容清成空白、启用状态原子持久化、用户目录同名插件覆盖内建版本、清单非法的插件可见但不可启用。

## 候选池

双 lane 提案去重后的初始池（2026-09-24 首轮 10 个提案收敛为 5 个共识方向）：

| 方向 | 维度 | 来源 | 状态 |
|---|---|---|---|
| 采集去重 + 微信复制图片偶发双份修复 | 功能/工程 | 双 lane 共识（各列第 1） | 候选 |
| 全局快捷键唤起与键盘直达（唤出/贴出最近一条/数字键取用） | 交互/功能 | 双 lane 共识 | 候选 |
| 内容搜索与筛选（类型/分类/时间，只读视图） | 功能 | 双 lane 共识 | 候选 |
| 撤销与回收站（Ctrl+Z、批量恢复、容量上限） | 可靠性 | 双 lane 共识 | 候选 |
| 缩略图异步解码/缓存 + 分类切换即时反馈 | 性能/动效 | 双 lane 共识 | 候选 |
| 分类标签内容直接编辑 | 交互 | 用户指定 | 候选 |
| 分类标签字体清晰度优化（WPF 文本渲染） | UI | 用户指定 | 候选 |
| 插件系统二阶段（动作钩子、内置功能插件化、脚本插件评估） | 架构 | 用户指定方向 | 候选 |
| 动态分类增删 / 外部拖入激活方式 / 快捷启动 / 常驻模式 / 剪贴板采集开关 | 功能 | ROADMAP 既有 | 候选 |
| 项目层面：文档索引、命名与仓库卫生 | 工程 | 用户指定 | 候选 |

每晚未采纳的提案在沉淀阶段合并进此表；已完成的移入 `ROADMAP.md` 最近完成。

## 提案 worker 提示词模板

fanout 前把材料贴进模板，任务文件写到系统临时目录（不进仓库）。worker 无联网，"调研"仅指其已有知识，采纳前由主代理核实时效事实。

```text
你是一名资深桌面软件产品与工程顾问,专注 Windows 桌面工具类应用的长期打磨。任务:为一个名为「悬浮中转站」的软件提出 5 个最值得做的改进方向,覆盖功能、交互、UI 动效、性能、工程质量、文档等任意维度,但要优先选择"普通用户能直接感知价值"的方向。
你没有任何工具,不能联网、不能读写文件,仅凭下面给定的材料作答。

【输入材料】
{≤2000 字现状材料,含:软件定位、已有能力、不可动摇边界、已在候选池方向(勿重复)、已知弱点}

【输出要求】
- 只输出 5 个方向,每个方向给出:标题、维度、现在的问题或机会、建议做法、用户价值、成本(S/M/L)、主要风险
- 语言:中文;不确定的内容用 UNKNOWN 占位,不要编造
- 不要输出客套话或与 5 个方向无关的内容
```

## 记录

每晚在 `docs/research/loop-<YYYY-MM>.md` 追加一节：日期、提案摘要（双 lane 各 5 条的标题）、选中项与理由、实现范围、质量门与发行结果、失败与降级如实记录。该文件随代码提交，是改进循环的唯一运行史。
