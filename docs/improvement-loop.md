# 持续改进循环

这份文档定义"悬浮中转站"的夜间自动改进循环：谁提方向、怎么选方向、怎么落地、哪些既有设计绝对不能被新功能改回去。自动任务与人工会话都按本文执行；与 `AGENTS.md`、`PROJECT_GUIDE.md` 冲突时以后者为准。

## 第一性原理：三类算力各司其职

| 算力 | 特点 | 分配的工作 |
|---|---|---|
| wbx 双 lane（WorkBuddy · DeepSeek V4.1 Flash，国际版免费 + 国内版近免费） | 无工具、纯文本进出、单轮完成、近零成本 | 发散：提案、评审给定材料、批量文本 |
| GLM 5.3 / 5.3 Flash（主代理） | 有工具链、能写代码、能联网 | 收敛决策、调研、实现、测试、发布 |
| 夜间窗口（23:00–09:00 整点接力） | 5.3 Flash 几乎不限量 | 自动任务排在这个时段 |

外部 worker 的提案是**原材料**，不是决定。所有采纳都要经主代理按决策框架校验；worker 结论中涉及时效的事实必须由主代理核实。

## 每晚流程（整点接力，23:00–09:00）

自 2026-09-25 起夜间循环以"整点接力"机制运行：自动化 `悬浮中转站夜间持续改进整点接力` 在 23:00–08:00 每整点触发一次，同一会话尽量连续完成多个切片，整点触发只作为断电/崩溃后的接力兜底。以执行者手册为准；本节为机制摘要：

1. **初始化与锁**：≥09:00 只写收尾日志；`.zcode/nightly/lock.json` 的 heartbeat 距今 <90 分钟则退出（另一会话在工作），否则接管并随阶段刷新；读 `.zcode/nightly/state.json` checkpoint，优先恢复进行中切片。
2. **工作来源**：checkpoint 恢复 > 本文候选池 > wbx 双端提案 > README"当前限制"与 `docs/observations.md` 已知问题。
3. **切片闭环**（单项 ≤90 分钟，08:30 后不开新片）：对照冻结清单选最小垂直切片 → 分支 `feature/nightly-<YYYYMMDD>-<slug>` → 可委派部分 wbx fanout（产出一律是草稿，逐行审查后才集成）→ 补自动回归（UI/交互变化以 `FTS_PREVIEW_DATA_DIR` 隔离实例取证）→ 质量门四连 → CHANGELOG 未发布区 + `version.txt`（修复=patch，新功能=minor）→ 提交、推送、PR、等 CI（Windows + Apple Silicon）绿 → 合并 main → 统一发行（同一 GitHub Release 放 Windows 安装包与 Apple Silicon Mac ZIP，附 SHA256SUMS.txt，Mac 如实标注未公证测试状态）→ 本机优雅关闭、静默原地更新、重启验证版本与自启。
4. **无人值守决策**：绝不提问；冻结冲突→换方向；越权操作→不做并记录；拿不准→选风险更小的做法；一切待用户裁决事项记入当月 loop 日志"待裁决"清单。
5. **收尾**（09:00、无可用工作项或不可抗中断）：删 lock.json，checkpoint 写终态，loop 日志追加当晚汇总（切片数、合入与发版、失败与降级、待裁决）并提交推送。

Mac 端暂停开发期间：不改 Mac UI；共享 Core 改动必须保证 Mac 测试与 Apple Silicon CI 不回归；仅做恢复绿色的最小修复。

## 决策框架

对每个候选按四维打分（1–5）：

- **用户感知**：普通用户每天能感到的变化吗？
- **成本**：当晚能否以最小垂直切片完成（S ≤ 半晚，M ≤ 一晚，L 需拆分）？
- **风险**：触碰冻结清单或持久化语义的减分；纯增量加分。
- **共识**：双 lane 是否同时提出；是否在候选池里被反复触发。

得分相同取用户感知更高者。`L` 级方向先产出设计文档进候选池，不当晚硬做。

## 设计冻结清单（新功能不得回退）

以下是已设计定型的行为，除非用户当次明确要求，任何改动不得改变它们；发现冲突时停下来问用户，不自行动刀：

1. 磁盘写入原子性；保存失败时对象、状态、顺序、选择与滚动位置恢复（`LocalStore`/`BoardMutationService`）。
2. 分类内始终先置顶区后普通区；批量操作保持源显示顺序；批量拖放保持源数据与选择作用域。
3. 卸载只删除应用登记并管理的 `Data` 目录，不扩大到用户选择的父目录。
4. 复盘标签不接收剪贴板或拖放内容；按天 Markdown、自动保存与外部变更合并语义不变。
5. 设置改动即时生效并自动原子保存；开机自启 Run 值只在用户显式切换时写入。
6. 贴边一侧窗口边缘与屏幕平齐；右缘裁切、展开/收起节奏与既有动效开关语义不变。
7. 编辑器（含分类改名）持有键盘焦点期间面板不自动收起。
8. 单实例锁；安装/数据目录只认安装器登记；`version.txt` 是唯一版本来源。
9. 插件系统边界（1.9.0 起）：声明式清单、默认全部禁用、插件不得把内容清成空白、启用状态原子持久化、用户目录同名插件覆盖内建版本、清单非法的插件可见但不可启用。
10. 连续重复采集抑制（1.9.1 起）：只与"最近一条成功采集"比对，窗口 5 秒；文本比对整理插件处理后的全文，图片比对规范化后的像素指纹（跨表示互认）；仅作用于剪贴板自动采集的单条内容，批量多条导入与外部拖入永不因重复被抑制；保存失败不记录指纹。

## 提案 worker 提示词模板

fanout 前把材料贴进模板，任务文件写到系统临时目录（不进仓库）。worker 无联网，"调研"仅指其已有知识，采纳前由主代理核实时效事实。

```text
你是一名资深桌面软件产品与工程顾问,专注 Windows 桌面工具类应用的长期打磨。任务:为一个名为「悬浮中转站」的软件提出 5 个最值得做的改进方向,覆盖功能、交互、UI 动效、性能、工程质量、文档等任意维度,但要优先选择"普通用户能直接感知价值"的方向。
你没有任何工具,不能联网、不能读写文件,仅凭下面给定的材料作答。

【输入材料】
{≤2000 字现状材料,含:软件定位、已有能力、不可动摇边界、已在候选池方向(勿重复)、已知弱点}

【输出要求】
- 只输出 5 个方向,每个方向给出:标题、维度、现在的问题或机会、建议做法、用户价值、成本(S/M/L)、主要风险
- 语言:中文;不确定的内容用 UNKNOWN 占位,不要编造
- 不要输出客套话或与 5 个方向无关的内容
```

## 记录

每个切片闭环后在 `docs/research/loop-<YYYY-MM>.md` 追加一节：日期、方向与决策理由、实现范围、委派情况、质量门与 CI、发行与装机结果；未采纳但可留的提案并入候选池。当晚收尾时追加汇总（切片数、合入与发版版本、失败与降级、**待裁决清单**）。该文件随代码提交，是改进循环的唯一运行史。
