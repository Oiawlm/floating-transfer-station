|---|---|---|---|
| 使用问题（功能行为/边界/快捷键） | [操作手册](usage.md) | 想知道某项功能的完整行为、边界与失败处理时 | 门面 README 只留速览与导航，细节以手册为准 |

## 披露原则

文档与设置界面共享同一套渐进式披露：信息按「读者当下任务所需的最小集合」分层就位，越常需要越浅、越少需要越深。新增或改动内容时按判据归层；同一信息放两处判据之外的副本是腐化之源。

| 层 | 文档面 | 设置界面 | 准入条件 |
|---|---|---|---|
| 路由 | 本文件任务路由表 | 左侧导航 | 任务类型→文档/页面的稳定映射，能写清何时读/别读 |
| 正文 | 各文档正文 | 内容页设置卡 | 单一主题的完整知识，按任务整篇/整页取用 |
| 细节 | 正文内小节 | 一句话说明＋ToolTip | 主流程不需要、遇到疑问查证才需要：边界、失败处理、联动副作用、数值范围 |

- 细节层红线：隐私与数据外发、默认值变化、不可逆操作三类信息必须常可见，不得只收进 ToolTip；说明句与 ToolTip 不重复同一信息。
- 成熟度分层与上表正交：语义仍可能推翻或需真实反馈的能力标「实验性」，集中置于「通用 → 实验性」（依赖同域共享配置的留所在页并标注）；默认态按成熟度定，日常可用→默认开、边缘体验→默认关；连续两个版本无语义修订且无报障即可毕业为默认开启，语义稳定后移出「实验性」标注，方向被推翻则删开关退役。
- 功能溯源表维护：一行一版本、锚点指向 CHANGELOG 版本节；版本内多项用户可见变化以「/」并入，超长再拆子行；内部重构与纯修复不进表；历史行只增不改。

维护者本地的常驻规则与设计契约不入库，与本页公开路由互补分工：重叠文档的指向两处必须一致，公开行改动须同步维护者路由。
