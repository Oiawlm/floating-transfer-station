# 悬浮中转站 README 视觉资产规划

## 一、第一性原理：README 各章节在服务什么决策

### 1.1 读者决策链

README 的读者不是"读文档"，而是依次做一串**采纳决策**。每一节只服务其中一个决策，图只有在"能改变该决策"时才有存在价值。

| 读者此刻的决策 | 对应章节 | 决策失败的代价 | 该决策靠什么才能被满足 |
|---|---|---|---|
| 这是什么？值得我继续读吗 | 标题 + 一句话简介 | 3 秒内离开 | 产品**形态**与**运动特征**（贴边、自动收起、拖出） |
| 我的机器能装吗？Mac 是不是正式版 | 平台/版本引用块 | 白下载、装不上 | 逐字准确的版本与支持边界 |
| 装起来麻烦吗？会不会污染系统 | 下载与安装 | 放弃安装 | 步骤顺序、可选目录的空间关系 |
| 它能解决我的问题吗 | 它能做什么 / 复盘标签 | 核心流失点 | 能力断言需要**被看见**，而非被相信 |
| 具体怎么按 | 几个常用操作 | 用不起来 | 键位与 UI 位置的精确对应 |
| 数据在哪？卸载会不会误删 | Windows 数据和卸载 | 不敢用 | 精确路径与行为契约 |
| 边界与坑 | 当前限制 / Mac 版 | 装了才发现不合用 | 负面契约，必须诚实 |
| 我要不要参与开发 | 本地开发 / 参与贡献 | 无关流失 | 可复制的命令 |

**核心判断**：这份 README 的文字承载"**契约**"（路径、键位、版本、限制、命令），图承载"**证明**"（声称的行为真的会发生）。二者不可互换——用图承载契约会失真且过期，用文字承载行为会让读者只能"相信"。

### 1.2 媒介选择的三条判断标准（按优先级）

**标准 1：时间本身是不是信息？**
如果卖点在"状态随时间变化"（拖拽、自动收起、悬停展开、自动保存、批量选择），必须动图——静态图会丢掉唯一的信息维度。如果卖点是"静止的形态/密度/布局"（设置窗口、UI 结构），静态图足够且体积小一个数量级。

**标准 2：信息是不是可复制、可校验的契约？**
路径、快捷键、命令行、版本号、像素上限——文字才是权威媒介。截图里的文字**不可复制**、**不可搜索**、**随环境漂移**，属于净损失。

**标准 3：一条资产只证明一个声明。**
把"复制→入库→整理→拖出"压进一条 GIF 会让人看不懂在演什么。例外：Hero 图可以用一条完整链路建立整体心智模型，之后的功能图必须切换到**近景单动作**，且与 Hero 的取景不重复。

**排除条件**：真实产品里没有可见画面（本地保存、编码上限），或没有该平台的画面（Mac 版），一律不加图——伪造画面比没有画面更糟。

### 1.3 逐章节推导

| 章节 | 读者决策 | 信息性质 | 媒介结论 | 理由 |
|---|---|---|---|---|
| 标题 + 一句话简介 | 是否继续读 | 产品身份、整体形态 | **动图（Hero）** | "贴在屏幕边缘""空闲时收成标签"是运动特征，一句话说不清；这是唯一值得用最贵预算的图 |
| 平台/版本引用块 | 能否安装 | 版本契约 | **不加图** | 版本号与支持范围必须逐字准确，图无法承载且必然过期 |
| 下载与安装 | 装起来难不难 | 链接、表格、目录选择 | 文字为主 + **可选 1 张静态图** | 表格已是最优媒介；仅"选择程序安装位置与内容存储父目录"这一步有空间关系增益 |
| 它能做什么 | 能否解决我的问题 | 能力断言，多为时间行为 | **动图为主 + 1 张静态结构图** | 每条 bullet 是一个断言，动图是成本最低的证明；结构图让读者在后续动图里认得出各部件 |
| 复盘标签段落 | 要不要用它写日报 | 交互节奏 + 文件落盘 | **动图** | "停止输入自动保存""切换历史日期"是时间行为 |
| 几个常用操作 | 具体怎么按 | 键位精确映射 | **不加图** | 键位必须可复制可校对；UI 位置已由结构图覆盖 |
| Windows 数据和卸载 | 数据在哪、会不会误删 | 路径与行为契约 | **不加图** | 精确路径无法用图承载；资源管理器截图只是一台机器的目录视图 |
| Mac 版 | Mac 能不能用、可信吗 | 验证/签名状态 | **不加图** | 本机无 Mac 画面；README 自身声明"Windows 截图不作为 Mac 实机证据"，加图即误导 |
| 当前限制 | 有哪些坑 | 边界与已知问题 | **不加图** | 限制是负面契约；B-005/B-006 为不可稳定复现的现场观察，录屏会制造误导性证据 |
| 接下来准备做什么 | 未来有没有我要的功能 | 未实现的规划 | **不加图** | 无真实画面，任何"效果图"都是伪造 |
| 本地开发 / 发布指南 | 怎么跑起来、怎么发版 | 命令 | **不加图** | 命令需可复制；终端截图随环境漂移 |
| 参与贡献 / 许可证 | 要不要提 PR / 合规 | 流程与法律文本 | **不加图** | 无视觉信息 |

## 三、明确不建议加图的章节

| 章节 | 不加图的理由 |
|---|---|
| 平台/版本引用块 | 版本号、支持矩阵、公证状态是逐字契约；图不可复制、不可校对，且每次发版都要重录 |
| 几个常用操作（快捷键长列表） | 键位需要可复制、可搜索、可校对；UI 位置已由 02-panel-anatomy 覆盖，再配图是重复信息 |
| Windows 数据和卸载 | `%LocalAppData%\...` 这类精确路径图无法承载；资源管理器截图只代表录制者一台机器，且可能泄露个人信息 |
| Mac 版 | 本机无 Mac 画面；README 自身写明"Windows 截图不作为 Mac 实机证据"，在此处放 Windows 图会直接误导。Mac 端开发已暂停，也无新增画面来源 |
| 当前限制 | 限制是负面契约，需精确措辞。B-005（图片分类反馈稍晚）、B-006（微信复制图片偶发生成两份）是**不可稳定复现的低优先级现场观察**，录屏会把它包装成"确定存在的问题"或反过来掩盖它，两种都是错误证据 |
| 接下来准备做什么 | 内容均为未实现规划，不存在真实画面；任何示意图都是伪造，违反"必须真实产品画面"的前提 |
| 本地开发 / 发布指南 | 命令是复制粘贴契约；终端截图不可复制，且随 dotnet 版本与终端主题漂移 |
| 参与贡献 | 流程约定，无视觉信息 |
| 许可证 | 法律文本，无视觉信息 |
| 「图片容错」「本地保存」两条 bullet | 前者是读取/解码失败后的内部降级策略，后者是磁盘行为，二者在界面上都没有稳定、可重复的可见差异；强行录屏只能靠制造异常，得不偿失 |

## 四、体积预算（GitHub README 场景）

### 4.1 总量

- **总预算（全部资产提交进仓库）：目标 ≤ 9 MB，硬上限 ≤ 12 MB。**
- P0 合计 ≈ 7.0 MB；P0 + P1 合计 ≈ 8.9 MB；全部含 P2 ≈ 10.5 MB。
- **若超出目标：优先降 P2，再降 P1，P0 不动。** 降级方式按代价从低到高：缩短时长 → 缩小宽度 → 降帧率至 10fps → 改静态图 → 删除。
- 数量上限：GIF ≤ 6 条，静态图 ≤ 5 张，总计 ≤ 11 条。

### 4.2 单资产预算

| 类型 | 尺寸 | 时长 | 帧率 | 体积上限 | 编码要求 |
|---|---|---|---|---|---|
| Hero GIF | 960×540 | 6–8s | 12–15fps | 2.5 MB | 调色板量化（≤ 128 色）+ 去首尾静止帧 |
| 功能 GIF | 720×420 ~ 800×450 | 4–7s | 12fps | 1.5 MB | 同上；删除鼠标空闲段与中间停顿 |
| 静态截图 | 宽 ≤ 900 | — | — | 200 KB | PNG-8 / pngquant 量化；必要时裁掉纯色留白 |
| 双联静态图 | 宽 ≤ 900 | — | — | 300 KB | 同上，两张同尺寸拼接 |

### 4.3 制作与维护规范

- **录制**：本机 Windows 11 真实应用，禁止任何生成式或合成画面。只录"面板 + 目标软件窗口"区域，1280×720 录制后裁切，不要出现整屏桌面。录制前隐藏桌面图标、通知横幅、输入法候选窗、聊天列表与个人信息。
- **编码**：GIF 用 ffmpeg（`palettegen` + `paletteuse`）或 ScreenToGif 二次导出；首尾帧尽量一致以实现无缝循环；保持真实节奏，不加速或 ≤ 1.5×（05-edge-collapse 必须原速，否则"约 250ms 收起"会被误读）。
- **一致性**：同一批次资产统一缩放比例、统一主题（建议深色，与 Hero 一致）、统一面板位置，避免读者以为是不同产品。
- **维护成本**：UI 改动会使截图过期，因此**同一录制会话内一次性产出多条资产**；P0 资产在 UI 变更后优先重录。
- **图注与 alt**：见第二节末尾规范。

### 4.4 UNKNOWN（需确认，不编造）

- 演示用目标软件（记事本 / Word / 微信 / 浏览器）的最终选择，以及微信界面是否可公开录制 → UNKNOWN
- 最终录制与 GIF 编码工具选型（ScreenToGif / ffmpeg / ShareX）→ UNKNOWN
- 面板展开态的实际像素尺寸与最小宽度（影响裁切比例是否统一）→ UNKNOWN
- 仓库当前总体积、是否启用 Git LFS 或存在体积告警阈值 → UNKNOWN
- 仓库是否已有 `docs/images/` 目录及其现有内容 → UNKNOWN
- GitHub 对单文件 GIF 体积是否触发降级或提示 → UNKNOWN
