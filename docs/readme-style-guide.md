# README 风格指南

> **一句话定位**：本仓库 README 与对外门面文档的写作规范——把「3 秒懂 → 30 秒信 → 3 分钟装」的访客旅程落成可复用的决策规则；新增或修改根 README 前后按本指南执行，`docs/usage.md` 等门面配套文档参照执行。
> **来源**：`artifacts/readme-style-research/RESEARCH-V1.md`（唯一事实源：10 个软件类国产热门标杆仓库＋2 元参考，全部经 GitHub API 核实；本指南与 RESEARCH 冲突时以 RESEARCH 为准）。
> **日期**：2026-10-18（v1）　**行数预算**：≤250 行

## 0. 总则

- README 的本质是**项目门面**，不是操作手册。唯一使命：让陌生访客完成「3 秒懂（这是什么）→ 30 秒信（凭什么值得装）→ 3 分钟装上」。
- 每个排版决策必须能回答「它服务旅程的哪一步」；服务不到的内容**移入 `docs/` 或折叠，不删除**（信息零丢失）。
- 发现门面问题时不打补丁：先修本指南，再让 README 作为体系的应用回归合格；改了 README 而没沉淀规范的，视为未完成。

## A. 版面骨架

**A1 章节标准序**——章节按读者投入度递增排序，可省略、不可乱序：

1. 首屏：标题＋一句话定位＋hero 演示＋斜体图注（`<div align="center">` 包裹）
2. 徽章行：≤6 枚，统一 shields.io flat 风格（见 A2）
3. 状态说明：`> [!IMPORTANT]`（平台目标、停更历史等一票否决信息）
4. ✨ 功能特性：一行一条＝**粗体关键词**＋一句话（≤2 行），细节给锚点或外链
5. 📦 下载与安装（冻结段规则见 E2）
6. 🚀 常用操作速查：精选 ≤12 条高频 →「操作｜效果」两列表格
7. 📖 功能详解 → `docs/usage.md`（README 只留导航，不堆正文）
8. 🖼️ 界面一览：README 正文只保留 hero＋至多 3 张关键图，其余收入 `<details>` 折叠图集
9. 📁 数据与卸载
10. ⚠️ 当前限制
11. 🗺️ 路线图（链接 ROADMAP.md，README 不复述）
12. 🛠️ 本地开发（可照抄命令块）
13. 🤝 参与贡献（链接 CONTRIBUTING＋Issue 模板）
14. 📄 许可证
15. 可选折叠：致谢、Star History

- 正例：本仓库根 README 的章节序即按此骨架排列。
- 反例：旧版把 27 条操作细节平铺在门面正文「几个常用操作」——手册混进门面；应正文给速查表，全量给 `docs/usage.md`。

**A2 徽章**——数量 ≤6，两行分组：第一行工程信号（Release 版本、Stars、Issues），第二行平台与许可（平台、运行时、License）。版本徽章一律用动态 release 取数（`https://img.shields.io/github/v/release/<owner>/<repo>`），禁止把手写版本号放进徽章；不引入外链图床、不伪造 logo。

**A3 下载引导三段式**——最短路径（一张表直接给出当前正式版直链）→ 参数表（平台｜下载｜状态）→ 负面清单（无需另装依赖、源码包说明等打消顾虑的短句）。多发行版并存时可选「我应当下载哪个版本」三列表（版本｜适合谁｜下载），取舍代价写进「适合谁」列、状态写进版本名。

**A4 表 → 注 → 声明**——表格只放当前快照；时间性信息（升级路径、历史行为）进「注：」段或 `docs/usage.md`；README 不承载 changelog，版本变更只做索引句（链 CHANGELOG）。

**A5 平台矩阵**——平台×架构支持矩阵用 ✅ / `-` 两个符号，不支持写 `-` 不留空；复杂约束外置为表下注。

## B. 列表与序号

- **B1** 流程步骤＝有序列表 `1. 2. 3.`；安装、迁移、排障等按序操作必须有序。
- **B2** 并列能力＝无序列表＋**粗体前缀**（`- **关键词**：一句话`）。
- **B3** 快捷键、设置项、下载链接＝表格，列数 ≤4。
- **B4** 键盘按键一律行内代码（`` `Ctrl + F` ``）；命令块最小可粘贴（不带 `$`、不带行内注释），关键命令后补一句「会看到什么」。
- **B5** 密度上限：嵌套 ≤2 层；单条 ≤2 行（约 100 字符），超了就拆条、进表格、折叠或移出 `docs/`。
- 正例：`- **随手收集**：复制即入库，5 秒内不重复收集相同内容。`
- 反例：一条 400 字列表项把行为、边界、失败处理全塞进去（旧版「整理内容」条）——应拆为速览一行＋`docs/usage.md` 详解小节。

## C. 视觉件

- **C1** 截图一功能一图一图注；图注统一斜体模板 `*<画面在做什么>（<一句补充>）*`；宽度档位四档 880 / 720 / 560 / 400，同档尽量同宽。
- **C2** 变体图（深色主题、前后对比、备选样式）收进图注链接（`深色主题见 [x-dark.png](…)`）或 `<details>` 图集，正文不重复挂多张。
- **C3** 次要细节（历史兼容、图集、长清单）用 `<details>` 折叠；`<summary>` 自带「点击展开」类提示。
- **C4** callout 选型：`NOTE`＝补充说明；`TIP`＝旁支分流（可跳过）；`IMPORTANT`＝必须知道（平台目标、停更）；`WARNING`＝有代价的操作；`CAUTION`＝危险。禁用裸 blockquote 当提示。
- **C5** README 正文非折叠图 ≤4（hero＋至多 3 张关键图）；变体图不计入正文但必须随图注可达。
- 正例：`*发现新版本：头部最左「更新」按钮点亮，点击即自动下载安装并重启*`
- 反例：`**批量复制**` 伪标题＋裸图＋图注堆叠——伪标题不是标题，层级只靠真标题与折叠维护。

## D. 中文排版

全量采用《中文文案排版指北》与 ruanyf 文档规范的细则，以下为本项目强制项：

- **D1** 中英文之间加一个半角空格；中文与数字之间加空格；数字与单位之间加空格（16 GB；90°、15% 例外）。
- **D2** 中文语句用全角标点，整句英文或代码才用半角；全角标点前后不加空格；标点不叠用、少用感叹号。
- **D3** 并列用顿号「、」；省略号用「⋯⋯」；标题末尾不加标点。
- **D4** 专有名词正确大小写（GitHub、Windows、DeepSeek、WPF、.NET）；不生造缩写。
- **D5** 引号全文统一「」；术语全文统一（「发行版」或 Release 二选一：中文叙述用「发行版」，GitHub Release 作为专有名词除外）。
- **D6** 数值用半角数字＋千位分隔符（6,400 万像素）；数值范围两侧带单位（2～24 小时）。
- **D7** 一段一个中心句、最佳 ≤4 行；标题不跳级，四级标题改用列表；同级仅剩一个标题时删掉该级。
- **D8** 本项目路径书写与安装器字面一致：「悬浮中转站Data」（中间无空格）、`%LocalAppData%\Programs\悬浮中转站\`。

## E. 版本化联动（本项目根因规则）

- **E1** 版本展示一律用动态徽章（A2），正文不写「最新版本是 x.y.z」。
- **E2** 「下载与安装」节是**发行列车冻结段**：版本号、发行页 URL、安装包文件名、`SHA256SUMS` 表述等事实 token 只在发行列车（`docs/releasing.md`）从 main 改动；普通分支改 README 不得触碰——排版可调，token 逐字保留；没把握就整节原文保留。
- **E3** 正文散落的版本号注（「1.20.0 新增」类）可精简，但须先对照 `docs/README.md` 功能溯源表与 CHANGELOG 确认该事实已有公开记录。
- **E4** 内部编号（B-005/B-006 等观察编号、设计契约编号）不得出现在公开 README；对应事实（已知问题、低优先级、未能稳定复现）保留。
- **E5** 每次发版改 README 前过一遍 §F 清单，并留验证证据。

## F. 质量清单（每次改 README 必过）

1. **信息零丢失**：old→new 逐节映射表，移出内容有去处（新 README 或 `docs/usage.md`）；删减只允许「迁移」与「去重合并」，合并前确认两处确为同一事实。
2. **资产**：引用的每个 `docs/images/*` 与相对链接 `git ls-files` 命中（0 MISSING）。
3. **链接**：含锚点全部可达（渲染 HTML 后核对锚点 id）。
4. **渲染**：GitHub 渲染验证（`gh api markdown` 或浏览器）＋截图留档 `artifacts/`（不入库）。
5. **徽章**：全部返回 200 且风格统一（flat）。
6. **排版**：§D 中文排版抽查；列表项无超过 200 字符的单条。
7. **冻结**：「下载」段 token（版本号 / URL / 文件名）与变更前逐字一致（除非本轮属发行列车）。
